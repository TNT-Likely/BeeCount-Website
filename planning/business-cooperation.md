# BeeCount 商务合作：官网落地与 Cloud / App 后续方案

日期：2026-10-04。状态：官网首版已实现；Cloud / App 为待评审方案，本次不改动它们的运行代码。

## 目标与合作优先级

1. **P0：合规 AI 模型 / API 服务商**。优先争取用户专属额度或优惠，以及现金赞助或推广分成；开发额度单独记录，不等同于收入。核验实际 API 使用场景，不能把仅适用于编程工具的套餐当作通用记账 API。
2. **P1：官网品牌展示**。按位置、期限和素材商议，可与 README 组合。
3. **P2：主仓库 README 品牌展示**。Logo、短介绍和链接组成独立赞助区，不改变安装说明和功能文档的阅读顺序。

初期不公开虚构的曝光、转化率、合作伙伴和报价。评估以真实接入效果、厂商提供的汇总推广数据、用户反馈及现金收益为依据，不收集账本内容作为商业统计。

## 扩展合作方式

首页继续保留原有三张卡片；合作页新增「项目赞助与生态共建」，容纳长期项目赞助、Cloud 部署合作和公共功能共建。商业授权与部署服务沿用商务邮箱咨询。

| 方式 | 可洽谈内容 | 交付边界 |
| --- | --- | --- |
| AI 官方场景合作 | 接入适配、模型测试、教程、用户专属权益、厂商案例收录与联合推广；争取现金赞助 | 能力验证与合作展示分开，赞助不能替代技术测试或决定默认服务商 |
| Cloud 部署合作 | 与云服务、NAS 或部署平台共建安装、升级和备份方案；商议推广收益或技术服务费 | 先做一个完整部署方案，明确升级兼容、备份恢复和支持责任，保留用户的部署选择 |
| 长期项目赞助 | 季度 / 年度维护支持，官网与 README 致谢，定期项目进展 | 不以用户数据或功能付费墙换赞助，不承诺无限开发需求或占用全部路线图 |
| 公共功能共建 | 企业支持导入适配、无障碍等通用功能，按里程碑交付 | 先判断是否适合主线；确定开发范围、验收及维护预算，成果按项目既有许可证向所有用户开放 |
| 商业授权与部署服务 | 授权、部署、迁移、培训等标准化服务 | 明确许可证、服务内容和支持期限；深度定制单独评估，避免无限售后 |

建议洽谈顺序：AI 用户权益 + 现金赞助 + 联合推广 → Cloud 部署伙伴 → 季度 / 年度项目赞助 → 有明确预算与范围的功能共建或商业服务。该顺序用于拓展合作，不改变首页现有展示优先级。

合作渠道参考：[硅基流动生态共建计划](https://siliconflow.cn/partner)公开介绍技术协作、Token 扶持与联合推广；[阿里云计算巢](https://help.aliyun.com/zh/compute-nest/)提供软件部署与交付能力。这里只记录调研方向，不表示已经合作、符合入驻条件或获得相应权益，接洽时单独核验。

## Cloud：先提供低打扰入口，再考虑服务商权益

### 第一阶段：关于弹窗中的商务联系

现有入口：头像菜单 →「关于」，组件为 `frontend/apps/web/src/components/AboutDialog.tsx`。

建议在项目仓库区域之后增加一条次级「商务合作」链接，根据界面语言打开官网合作页，并明确是 BeeCount 项目方的合作渠道。新窗口打开，保留当前账本操作上下文。不要让使用自建实例的普通用户误认为该链接属于实例运营方。

不放入仪表盘、交易列表、记账编辑器、登录注册流程或同步失败提示。自建实例运营者应可通过实例级配置隐藏项目商务入口；上线前确定默认行为，不把营销内容强制推给所有部署。

### 第二阶段：AI 配置内的可选服务商介绍

现有页面：`frontend/apps/web/src/pages/sections/SettingsAiPage.tsx`，已有服务商管理和能力绑定。

有真实合作权益和适配结果后，才在服务商管理附近提供可折叠的「服务商与合作权益」。优先保留已有配置、添加自定义服务商、能力测试等操作；广告或赞助关系清晰标注，用户能够忽略或隐藏推荐。

每项列出支持能力、适配过的模型、限制、权益资格与期限、第三方隐私说明及合作关系。用户点击后才访问厂商；推广参数不得包含实例地址、用户标识、账本、模型对话、API Key。不自动注册、不替换已选服务商、不把赞助金额当作技术排序依据。

实例默认不拉取远程营销素材。若将来支持更新清单，需要实例运营者明确启用、有缓存和失败回退，商业网络请求失败不能影响记账或 AI 配置。

## App：商务联系与消费优惠分开评估

### 保持核心体验

不增加首页 Banner、启动弹窗、记账后插屏、积分任务或推送促销。继续保持 App 内无广告，不将官网广告搬进客户端。

商务联系的潜在入口是「我的 → 关于」，现有文件为 `lib/pages/settings/about_page.dart`。如后续确定增加，建议只提供一条次级「商务联系」和邮箱，面向授权 / 部署 / 定制 / 企业合作咨询，不指向包含 Token 购买、优惠及充值链路的官网合作页。**这是降低干扰的设计建议，不保证审核通过；首阶段暂不实现。**

AI 服务商选择属于功能配置：可以提供经验证的能力说明、模型测试和中立的帮助信息。不要因付费合作添加默认推荐、限时优惠、购买 / 充值按钮；不要求用户通过推荐链接开户才能记账。

### 分发渠道与审核边界

| 渠道 | 建议 | 上线前需要核验 |
| --- | --- | --- |
| App Store | 先保留 BYOK 配置；暂不新增厂商购买 / 注册推广入口 | 数字服务消费位置、完整外链路径、目标 storefront、适用授权与最新规则 |
| Google Play | 同样先保持中立配置与帮助 | Payments policy 适用范围、目标市场及是否参加允许外链的计划 |
| GitHub 直装 Android | 后续可单独评估用户主动打开的厂商权益页 | 厂商资质、服务条款、隐私告知及 App 无广告承诺；直装不等于免责 |

渠道差异应由可审查的构建渠道和实际政策条件表达；不得识别审核人员、审核期间关掉入口后再打开，或靠远程开关规避审查。地区判断不能只依赖界面语言。

在通用版本中，不以美国等市场的例外作为全球可用依据，也不直接认定 BeeCount 属于 reader app 或免费伴随 App 豁免。

- `lib/pages/settings/help_center_page.dart`、`lib/utils/website_urls.dart`：检查 WebView 导航、外部浏览器打开、语言切换、重定向和帮助文档中的注册链接。
- 官网 `docs/ai/overview.md` 已有厂商注册 / 邀请链接；本次没有调整这些旧内容。新合作入口隐藏不等于已有帮助链路已全部通过审核评估。
- `lib/pages/settings/about_page.dart` 已有渠道差异和捐赠入口：避免把商务合作复用成购买入口。

## 官方规则依据与推断

核验日期：2026-10-04；规则可能更新，实际提交前重新查阅。

- [Apple App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/)：3.1.1 和 3.1.1(a) 规定数字内容 / 服务付款与外部购买链接，部分 storefront 和授权存在不同规则；3.1.3(f) 的免费伴随 App 条件不代表所有免费 BYOK App 都自动豁免；2.3.1 要求功能透明、禁止隐藏未披露功能。
- [Google Play Payments](https://support.google.com/googleplay/android-developer/answer/9858738?hl=en)：适用的数字商品 / 服务付款和外部导流要求，以及列明的例外。
- [Understanding Google Play’s Payments policy](https://support.google.com/googleplay/android-developer/answer/10281818?hl=en)：帮助中心等管理信息页面也要检查是否最终导向被禁止的付款方式；不同渠道可采用不同功能，但须遵守各自规则。

**设计推断**：用户购买的 Token 若用于 App 内 AI 功能，促销、领取额度、注册与充值的完整路径可能涉及数字服务的付款政策。不能仅凭「第三方厂商」「浏览器打开」「只卖 Token」「文案是免费额度」就认定安全。商务邮件咨询和消费推广也不能混为一个页面。

## 实施顺序与验收

1. 官网首版 PR：中英文、桌面 / 手机、浅色 / 暗色、入口和邮件模板；内嵌模式不展示新招商入口。
2. 用户确认后，Cloud 单独 PR：先做关于入口和实例运营者控制，保持账本任务连续性。
3. 确定真实厂商、权益、资质及能力适配后，另提 Cloud AI 服务商权益方案。
4. App 单独评审：先做已有外链审计及各分发渠道评估，再决定是否加商务联系；消费优惠方案后置。
5. 若最终出现购买入口，需要完整设计目标地区的授权 / 计费路径与审核说明，再进入客户端实现。

后续主仓库 README 可把已有商务合作链接指向官网，并把「零广告」明确为 App 范围；Cloud README 同样增加次级商务入口。这些调整分别放进对应仓库 PR。

验收标准：记账路径无额外点击或营销阻塞；已有 AI 服务商选择不变；商业内容不接触账本或 Key；活动失效有撤回方案；App 和内嵌帮助使用真实渠道规则验证。若需要设备验证，先按项目要求备份，禁止用用户正式应用包运行 Flutter 集成测试。
